Gears helps customers of a made-up bike shop check on a repair by typing a ticket ID like R101. It looks the ticket up in a small tool class and replies with the status, or says it couldn't find the ticket. The mock parts are the replies, which come from simple keyword rules instead of AI, and the ticket data, which is a hard-coded dictionary. Refunds, cancellations, and complaints go to the shop manager because they involve money or judgment that a rule-based helper shouldn't decide. 

## Adding a model

I added a real model granite4.1:3b through Ollama to handle everything the rules don't cover. It answered "where is the shop" well, replying "The shop is at 12 Main Street." because that fact was in its instructions. It could not answer "what are your hours" or "do you fix e bikes," and it said it did not know instead of making something up, which is what the instructions told it to do. The wording was awkward, though, because it said it "can offer to pass the customer to the shop manager" instead of actually offering to the customer. I kept ticket lookups and the refund, cancellation, and complaint handoff in code because they must be right every time, and a model could invent a status or promise a refund. The model only handles open-ended questions, and if it has no answer the helper gives a safe reply.
